# ADR 0002 — Norme du langage C : C17

- **Statut** : accepté
- **Date** : 2026-10-23
- **Jalon** : M0
- **Exigences liées** : ENF-03, ENF-21, FFI-01

## Contexte

Tout le code C du projet (noyau, mini-libc, firmware M33) doit être compilé
avec une norme fixée par `-std=`, faute de quoi chaque compilateur applique
sa valeur par défaut.

Plusieurs outils lisent ce code en plus du compilateur :

- `cppcheck` pour le sous-ensemble MISRA C (ENF-21) ;
- `clang-tidy` pour l'analyse statique (ENF-03) ;
- `bindgen`, via libclang, pour générer les bindings Rust depuis `include/` (FFI-01) ;
- éventuellement `arm-none-eabi-gcc` pour le firmware du Cortex-M33 (M8).

## Décision

Le code C est compilé en **`-std=c17`**, sans extensions GNU implicites.

Les extensions nécessaires s'écrivent sous leur forme réservée : `__asm__`,
`__attribute__((...))`.

## Justification

1. **MISRA C.** MISRA C:2023 couvre C11 et C17. Aucune édition ne couvre C23 :
   du code C23 sortirait du périmètre des règles vérifiées par ENF-21.
2. **Outillage.** C17 n'apporte que des corrections à C11 ; c'est la norme la
   mieux supportée par l'ensemble des outils listés ci-dessus.
3. **Pratique du domaine.** Le noyau Linux est passé à C11 (`gnu11`) en 2022 :
   le code noyau privilégie une norme stable et outillée.
4. **Explicite.** Sans extensions GNU implicites, tout ce qui sort du C
   standard est visible dans le code par son double underscore.

## Alternatives rejetées

| Option | Raison du rejet |
| --- | --- |
| `-std=c23` | Hors du périmètre MISRA ; support variable selon les outils et les versions de GCC. Apporterait `[[noreturn]]`, `nullptr`, `constexpr`, les littéraux binaires. |
| `-std=gnu17` | Active les extensions GNU sans les rendre visibles ; à réserver au cas où une extension sans forme réservée deviendrait indispensable. |
| `-std=c11` | Équivalent fonctionnel de C17, avec des défauts corrigés depuis. |

## Conséquences

- Les options de compilation C contiennent `-std=c17`, en plus de celles de
  la section 7 du cahier des charges.
- Les fonctions qui ne retournent pas sont marquées `_Noreturn` ; les
  vérifications à la compilation utilisent `_Static_assert`.
- Les booléens nécessitent `<stdbool.h>`, disponible en freestanding.
- À réévaluer quand une édition de MISRA C couvrira C23.
